# r20: browser speech synthesis (Web Speech API), research notes

Run r20-voice-article, worker "research". Searched 2026-10-17. Context: `site/talk/narration.html` reads the narration aloud with `window.speechSynthesis` / `SpeechSynthesisUtterance`, waits for `onvoiceschanged`, and speaks an empty utterance inside the click to unlock iOS.
Every claim has its source next to it. "Unconfirmed" means no primary source was found.

## 1. How it works, and where the voices come from

- **The API calls the operating system's speech engine.** MDN: "most OSes have some kind of speech synthesis system, which will be used by the API for this task as available." The page builds a `SpeechSynthesisUtterance` (text, voice, lang, rate, pitch, volume) and passes it to `speechSynthesis.speak()`. `getVoices()` lists the `SpeechSynthesisVoice` objects available. [MDN, Using the Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API/Using_the_Web_Speech_API)
- **`localService`:** "a boolean value indicating whether the voice is supplied by a local speech synthesizer service (`true`), or a remote speech synthesizer service (`false`)". MDN notes that remote voices may add latency, bandwidth or cost. Baseline "widely available" since September 2018. [MDN, localService](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService), [spec](https://webaudio.github.io/web-speech-api/#dom-speechsynthesisvoice-localservice)
- **Chrome on Windows, macOS and ChromeOS:** Chrome's TTS uses "Windows (using SAPI 5), Mac OS X, and ChromeOS, using speech synthesis capabilities provided by the operating system". [Chrome extensions, chrome.tts](https://developer.chrome.com/docs/extensions/reference/api/tts) This page documents the extension API, and we assume the web API uses the same back end (unconfirmed for the web API specifically).
- **Chrome "Google ..." voices are network voices.** Developer write-ups report that Chrome adds Google-hosted voices when a network connection is available, and that without a network only the OS voices remain. [thevalleyofcode](https://thevalleyofcode.com/lesson/ui-apis/speech-synthesis/), [flaviocopes](https://flaviocopes.com/speech-synthesis-api.md) These are secondary sources; no Google document was found.
- **Edge "Microsoft ... Online (Natural)" voices are cloud voices.** Microsoft: "Powered by Microsoft Cognitive Services", the voices have "'Microsoft <voiceName> Online' in their names", and "these voices have been exposed to developers through the JavaScript SpeechSynthesis API". [Microsoft Edge blog, 2019-08-14](https://blogs.windows.com/msedgedev/2019/08/14/cloud-powered-voices-microsoft-edge-chromium/) Edge's Read Aloud page says an internet connection unlocks the natural voices. [Edge Read aloud](https://explore.microsoft.com/en-us/edge/features/read-aloud) Edge's local voices are the Windows SAPI voices. Windows 11 "Natural Narrator" voices run on-device once downloaded ([Microsoft PDF](https://query.prod.cms.rt.microsoft.com/cms/api/am/binary/RW1kWWr)). Whether Edge or Chrome lists them in `getVoices()` is unconfirmed.
- **macOS and iOS (Safari and Chrome):** these browsers use Apple's system voices, which are local. The Apple licence calls them "System Voices" (see section 4). All iOS browsers use WebKit, so iOS Chrome gets the same voices. No primary source was found for that last point (unconfirmed).
- **Android Chrome:** reported to use the device's Android TTS engine (usually Google's). No primary source was found (unconfirmed).
- **Linux (Chromium and Firefox):** Chromium's Linux back end talks to speech-dispatcher, which usually drives espeak-ng. [Chromium tts_linux.cc](https://chromium.googlesource.com/chromium/src/+/lkgr/content/browser/speech/tts_linux.cc) Without speech-dispatcher, `getVoices()` returns an empty array. [Debian bug 809720](https://lists.alioth.debian.org/pipermail/pkg-chromium-maint/2016-January/007841.html), [Arch forum](https://bbs.archlinux.org/viewtopic.php?id=268799)
- **Privacy:** for any voice with `localService === false`, the utterance text must go to the vendor's server to be synthesised (Google for Chrome's "Google" voices, Microsoft for Edge's "Online" voices). This follows from MDN's "remote speech synthesizer service" definition. No Google or Microsoft document was found that describes what is sent, logged or kept (unconfirmed). A page that cares about privacy can filter on `v.localService`, and narration.html does not do this today. Managed Edge has a `ConfigureOnlineTextToSpeech` policy that turns the online voices off ([Tech Community thread](https://techcommunity.microsoft.com/discussions/edgeinsiderdiscussions/edge-version-150-javascript-speechsynthesis-getvoices-undefined-voices/4538591), community source).

## 2. Browser support and spec status

- **Spec:** "Web Speech API", a **Draft Community Group Report** of the W3C Audio CG. It is not a W3C Standard and not on the Recommendation track. The editor's draft was dated 15 October 2026 when fetched. [webaudio.github.io/web-speech-api](https://webaudio.github.io/web-speech-api/) caniuse labels it "Unofficial / Note". [caniuse](https://caniuse.com/speech-synthesis)
- **caniuse "Speech Synthesis API":** **95.91% of global usage** (StatCounter, September 2026; fetched 2026-10-17). Supported in Chrome 33+, Edge 14+, Safari 7+, Firefox 49+, Opera 27+, iOS Safari 7+, Samsung Internet 5+, Chrome and Firefox for Android. Not supported in IE, Opera Mini or UC Browser for Android. [caniuse](https://caniuse.com/speech-synthesis)
- **MDN** marks `SpeechSynthesisVoice.localService` as Baseline "widely available" (since September 2018). [MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)
- Support for the API does not mean voices are present. Headless Linux usually has none (see section 5).

## 3. Can the audio be saved to a file?

- **Not from the API.** The spec defines `speak`, `cancel`, `pause`, `resume`, `getVoices`, and events. It has no `MediaStream` or audio-buffer output. [spec](https://webaudio.github.io/web-speech-api/) Routing Web Speech audio to a chosen device has been an open request for years. [W3C public-webrtc-logs, mediacapture-output #102](https://lists.w3.org/Archives/Public/public-webrtc-logs/2020Sep/0208.html)
- **OS commands that use the same local voices:**
  - macOS: `say -o out.aiff "text"`. The man page says: "Specify the path for an audio file to be written. AIFF is the default…" `say -v '?'` lists the voices. [say(1)](https://www.unix.com/man-page/osx/1/say/) `--file-format=WAVE` is reported in secondary sources; check `man say` locally.
  - Windows: .NET `System.Speech.Synthesis.SpeechSynthesizer.SetOutputToWaveFile(path)` "configures the SpeechSynthesizer object to append output to a Waveform audio format file". This uses the SAPI voices, not Edge's online voices. [Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/api/system.speech.synthesis.speechsynthesizer.setoutputtowavefile)
  - Linux: `espeak-ng -w out.wav "text"` ([espeak-ng](https://github.com/espeak-ng/espeak-ng); the `-w` flag is from our own knowledge, so check `--help`). Piper is a "fast and local neural text-to-speech engine". The original `rhasspy/piper` (MIT) was archived on 2025-10-06, and development moved to `OHF-Voice/piper1-gpl` (**GPL-3.0**). [rhasspy/piper](https://github.com/rhasspy/piper), [OHF-Voice/piper1-gpl](https://github.com/OHF-Voice/piper1-gpl) Each Piper voice model has its own licence. Check the voice's model card (VOICES.md); per-voice terms are unconfirmed here.
- **Tab or system audio capture:** `getDisplayMedia({audio:true})` plus `MediaRecorder`. MDN: "Capturing audio is always optional… the returned MediaStream may still have only one video track, with no audio". The user must pick the source in a permission prompt, and the feature is not Baseline. [MDN, Using Screen Capture](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Capture_API/Using_Screen_Capture) In Chromium, tab audio works on all desktop OSes, and whole-system audio only on Windows and ChromeOS. [addpipe demo](https://addpipe.com/getdisplaymedia-demo/) (secondary). Whether speechSynthesis output counts as "tab audio" or comes from a separate OS process is unconfirmed. On most platforms the OS engine plays the audio, so it may not be in the tab's stream. Test before relying on it.

## 4. Licensing: can system voices be used to produce audio for publishing?

- **Apple, macOS Sequoia SLA, section 2.F "Voices; Live Captions"** (verbatim, from the PDF):
  > "you may: (i) use the system voices included in the Apple Software ("System Voices") (1) while running the Apple Software and (2) to create your own original content and projects for your personal, non-commercial use; … No other creation or use of the System Voices, Live Captions or Personal Voice is permitted by this License, including but not limited to the use, reproduction, display, performance, recording, publishing or redistribution of any of the System Voices, Live Captions or Personal Voice in a profit, non-profit, public sharing or commercial context."

  [https://www.apple.com/legal/sla/docs/macOSSequoia.pdf](https://www.apple.com/legal/sla/docs/macOSSequoia.pdf). Older macOS SLAs have the same clause ([10.7.2](https://www.apple.com/legal/sla/docs/macosx1072.pdf)), and iOS 18 has similar wording ([Apple dev forum, community answer](https://developer.apple.com/forums/thread/812285)). **Conclusion:** recording a macOS or iOS voice (`say -o`, or capturing Safari) and publishing it on a public site is a "recording, publishing… public sharing" use and is **not permitted**. A visitor's own browser speaking the page live on their own device is "use while running the Apple Software". This is our reading, not legal advice.
- **Microsoft Edge "Online (Natural)" voices:** no terms were found that cover recording or publishing their output. A Microsoft community volunteer said recordings may not be monetised ([answers.microsoft.com](https://answers.microsoft.com/en-us/microsoftedge/forum/all/how-to-record-the-audio-of-read-aloud-feature/8d1d6be2-2be4-4ba9-9742-f14ab164eb60)); this is not authoritative. **Unconfirmed.** Third-party libraries that call Edge's Read Aloud endpoint directly (e.g. `edge-tts-browser`) use an **undocumented** endpoint ([README](https://cdn.jsdelivr.net/npm/edge-tts-browser@1.0.1/README.md)). Avoid them for anything published.
- **Windows SAPI and Natural Narrator voices; Chrome's Google voices:** no licence clause found. **Unconfirmed.**
- **Safe options for published audio files:** an engine whose voice licence allows it (espeak-ng; a Piper voice whose model card allows commercial or public use), or a paid cloud TTS whose terms grant output rights. Live in-browser speech on the viewer's own device avoids the question for the publisher, because no audio file is distributed.

## 5. Playwright: can it create the audio?

- **Playwright's video has no audio, by design.** Issue #4870 "[Feature] Include browser audio with recordVideo" was closed on 2022-01-06. Pavel Feldman: "We concluded that this is outside of the scope for Playwright, so closing it as WontFix." [#4870](https://github.com/microsoft/playwright/issues/4870) The duplicate #16526 was also closed as "outside of the project scope for now". [#16526](https://github.com/microsoft/playwright/issues/16526) The video docs mention only viewport-sized video, saved when the context closes. [playwright.dev/docs/videos](https://playwright.dev/docs/videos)
- **Headless Chromium on a Linux CI runner normally has no voices.** `getVoices()` returns `[]` without speech-dispatcher ([Debian bug](https://lists.alioth.debian.org/pipermail/pkg-chromium-maint/2016-January/007841.html)), and this is a known headless fingerprint ([scrappey](https://scrappey.com/qa/anti-bot/what-is-speech-synthesis-fingerprinting), secondary). Even with voices, the audio goes to the OS sound device, not into the page.
- **What works instead:** (a) produce the audio outside the browser with a TTS engine that can write files (Piper, espeak-ng, or a licensed cloud TTS). (b) Record the video with Playwright. (c) Mux the two with ffmpeg. Community tools follow this pattern: `playwright-recorder-plus` "captures video frames only. Audio is added by scheduling clips… which ffmpeg muxes in afterward" ([repo](https://github.com/MuTsunTsai/playwright-recorder-plus)), and `playwright-recast` adds TTS voiceover from subtitles ([repo](https://github.com/ThePatriczek/playwright-recast)). Recording macOS voices this way is ruled out by section 4.

## 6. How common is it; good examples

No adoption figures were found, so none are given. These are the best concrete examples:
- **MDN "Speech synthesizer" demo**, the reference demo: https://mdn.github.io/dom-examples/web-speech-api/speak-easy-synthesis/ ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API/Using_the_Web_Speech_API))
- **addpipe TTS demo**, with a voice picker: https://addpipe.com/tech-demos/web-speech-api-text-to-speech-demo/
- **Read Aloud extension (LSD Software)** offers "voices provided natively by the browser" plus cloud voices: https://addons.mozilla.org/firefox/addon/read-aloud/
- **assistant-ui** (React chat UI library) ships a `WebSpeechSynthesisAdapter` so AI chat replies can be read aloud: https://www.assistant-ui.com/docs/guides/speech
- **Browser built-in read-aloud features** (the browser's own features, not the web API): Edge Read Aloud ([Microsoft](https://explore.microsoft.com/en-us/edge/features/read-aloud)), Safari "Listen to Page" in iOS 17 ([Simon Willison](https://til.simonwillison.net/ios/listen-to-page), [Dave Rupert](https://daverupert.com/2023/09/listen-to-page-mobile-safari-17/)), Chrome Android "Listen to this page", rolled out with Chrome 125 ([news](https://primetel.com.cy/chrome-on-android-introduces-listen-to-this-page-feature-6035)).
- **The read-aloud button pattern** (click an icon to speak a paragraph): [SitePoint](https://www.sitepoint.com/talking-web-pages-and-the-speech-synthesis-api/)
- Named language-learning products that use the web API: none confirmed.

## 7. Known gotchas

- **Chrome cuts off long utterances after about 15 s** with Google voices (reported since Chrome 55 on Windows and Ubuntu). Workarounds: split the text into sentences or paragraphs (narration.html already speaks per paragraph), or call `pause()`/`resume()` on a timer, which may fire spurious `end` events. [PhET issue #60](https://github.com/phetsims/utterance-queue/issues/60), [Caktus, 2025-11](https://www.caktusgroup.com/blog/2025/11/03/the-halting-problem/), [kartones](https://blog.kartones.net/post/web-speech-api/)
- **Voices load asynchronously.** In Chrome you must wait for `voiceschanged` before `getVoices()` returns the list. MDN's pattern is to call `populateVoiceList()`, then set `onvoiceschanged`. [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API/Using_the_Web_Speech_API), [monotonous.org](https://blog.monotonous.org/2021/speechsynthesis-getvoices/)
- **iOS needs a user gesture** before the first `speak()`. "iOS always requires a gesture for SpeechSynthesis to speak" ([WebKit bug 223473](https://bugs.webkit.org/show_bug.cgi?id=223473)). The usual fix is a first (possibly empty) `speak()` inside the tap handler, which narration.html does.
- **Ranges (spec):** rate 0.1 to 10 (default 1; engines may limit it further), pitch 0 to 2, volume 0 to 1. [spec](https://webaudio.github.io/web-speech-api/) narration.html clamps rate to 0.8 to 2.
- **Quality and naming vary by device.** The same page sounds different on each OS, voice lists differ, online voices need a network, and Firefox on Linux may have few voices ([addpipe](https://addpipe.com/tech-demos/web-speech-api-text-to-speech-demo/)). Edge 150 sometimes reported voice names as "Microsoft undefined Online (Natural)" (July 2026, community report, [Tech Community](https://techcommunity.microsoft.com/discussions/edgeinsiderdiscussions/edge-version-150-javascript-speechsynthesis-getvoices-undefined-voices/4538591)). Always keep a fallback to the default voice.
