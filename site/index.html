Run your Ruflo hive with a written mandate per role and a vault for what it remembers.

Ruflo is an agent meta-harness for Claude Code and Codex: a queen-led hive-mind, 100+ specialized agents, a policy engine with legacy, observe and enforce modes that writes a decision receipt for each action, and AgentDB memory with HNSW search. RuVector adds a self-learning vector database with sub-millisecond queries, native or in the browser; MetaHarness scaffolds your own focused agent harness, like Ruflo. sgit.ai builds on them: an Agent Behaviour Policy compiles into Ruflo's own enforce mode, and an sgit vault keeps the hive's memory files encrypted on your machine, versioned and cloneable.

ruv.sgit = a Ruflo hive + sgit vaults + Agent Behaviour Policies.

Measured here. POC1: the same 11 actions through Ruflo's policy engine, 6 stopped in enforce mode with ABP rules (4 denied, 2 sent for approval), both of Ruflo's hash-chained receipt ledgers valid. The ruv.sgit runner, every run in the ledger: an ephemeral vault, deleted after the run; none of the probed text from the delivered files found in any byte the vault server stored; a fresh clone identical to what was delivered.

Where sgit.ai plugs in

The ABP is a JSON document per deployment: for each agent role, what it can reach, what it is mandated to do, the gap between the two, the barrier that closes it, and the owner who answers for it, valid until a date. It compiles into the enforcement points rUv's stack already has.

The vault is where everything that must survive and be reviewed goes: the ABPs, the compiled policies, the receipts, the agent memory, the session records. Files are encrypted on the client before upload; the server stores ciphertext under opaque ids. One vault is published on purpose, with its read key, so you can open it: the public demo vault.

ABP (JSON) ──compile──▶ Ruflo AgenticPolicyEngine (allow / deny / approval + receipts)
           ──compile──▶ RVM capability rights (READ WRITE EXECUTE ... + withheld)
           ──render───▶ MetaHarness governance settings (diff both ways)
           ──render───▶ browser viewer (RuVector WASM search over ABP rows)

sgit vault ◀── receipts, reports, ABPs       (ruv-pocs-public, read key published)
sgit vault ◀── memory snapshots per agent    (ruv-pocs-memory, private)

USE CASE 1

Govern a swarm

Same swarm, same actions, both through Ruflo's policy engine: in its default legacy mode an agent may send email; in enforce mode with rules from the ABP it is denied, pushes go to a human, and Ruflo writes a receipt for every decision.

USE CASE 2

Remember across runs

Agents write memory on their own vault branch, it merges, and a fresh clone restores it. RuVector already keeps memory in files, with snapshots, copy-on-write branches and attestation; AgentDB adds a cryptographic witness chain. The vault adds client-side encryption and a shared, cloneable history around those files.

How →
USE CASE 3

Prove what happened

Hash-chained receipts from the policy engine, committed to a vault with the ABP that produced them. Tamper-evident, private, replayable.

How →
USE CASE 4

Publish only on approval

A deploy is an approval row. In CI that is a protected environment a named human approves; in the engine it is require_approval.

How →
USE CASE 5

Learn with rollback

SONA, ReasoningBank, Darwin mode change behaviour over time. Versioned ABPs and vault history show what changed, when, and let you revert a learned pattern.

How →
USE CASE 6

Run anywhere

The same ABP and vault in a GitHub Actions job, in a browser page with RuVector WASM, and in a Claude Code session with Ruflo as an MCP server.
