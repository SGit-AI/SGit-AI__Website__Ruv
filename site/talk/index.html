    Open the player on the laptop. Press A: an audience window opens. Drag it to the projector and press F there. The laptop now shows the presenter view; both windows share one clock.

  2. Start

    Press Space (or the clicker's play key) when you start speaking. The beats change on time without a click.

    Space pauses the clock. → or the clicker's next (PageDown) jumps to the next beat; ← goes to the start of this beat, twice quickly for the previous one. B blacks out the projector.

Questions to expect

"Isn't a scripted demo a fake demo?"

The terminal shows the command and the output the real run produced, captured beforehand and kept in the repository. Anyone can run it again from Replicate and compare. The live app beat is live.

"Did you bypass Ruflo's policy admin?"

No. Its CLI wants an interactive terminal for policy admin; POC1 uses the library engine, its documented programmatic surface. The Claude Code session (POC6) is a runbook for a human at the terminal.

"Why not just write Ruflo rules?"

You can. The ABP is the layer above: one mandate per deployment with the why and the barrier per row, compiled to Ruflo rules, RVM rights and CI gates. Change the mandate, recompile all three.

"Does sgit see my agents' memory?"

No. sgit encrypts on the client (AES-256-GCM); the server stores ciphertext. The public vault publishes a read key on purpose; the memory vault is private.

"Did the memory roundtrip run in CI?"

It ran locally end to end (two writers, a fresh clone, same answer). The CI jobs are wired on separate runners and need the vault secrets; say so plainly.

"What does this give a regulated organisation?"

A mandate a person can read and sign off per agent, enforced by the engine, and a hash-chained receipt for every decision, kept in a vault the host cannot read. That is evidence for an audit, not a certification.

"Is this upstream in rUv's projects?"

No. These are proofs of concept using pinned npm packages (MIT, by rUv / ruvnet). The ask is to pick one and build it together.

Rehearsals

Press R in the player at the start of a run-through and again at the end: it saves rehearsal.json with the planned and actual start of every beat. Drop it here to see the drift. A beat that starts more than ten seconds late is flagged; the same check runs from the command line with python3 site/build/rehearsal_check.py rehearsal.json.

Where this comes from

A voice memo by Dinis Cruz on 14 Oct 2026, written up as The scripted talk on the sgit newsroom: a talk as a timeline that plays on a clock. It grows out of two talks published as vaults: AI vs. AI at Black Hat Europe 2025 (slides as data) and the VoiceDebrief pitch (per-slide timings and a presenter). The first player was a prototype by the newsroom's agent; this one adds the audience window kept in sync with the presenter, clicker keys, a black screen, table rows read from the site's data, a live page that types its own question, an offline build with the images inside, and a timeline check that fails loudly if the beats do not add up.

What this does not claim

  • It has not been given yet: tested in headless Chromium, not in a room.
  • Scripted is not read: the words are in the presenter view; whether to read them is the speaker's choice.
  • The timings are a first cut; the rehearsal log is what tells.
