Run it on your laptop, offline

Just the talk and the site (no setup, no network; Python 3 only):

git clone https://github.com/SGit-AI/SGit-AI__Website__Ruv && cd SGit-AI__Website__Ruv
./run-website-locally.sh          # the same as: python3 -m http.server -d site 8080
# then open http://localhost:8080/talk/player.html?talk=talk-10.json   (or any page: http://localhost:8080/)

With no server at all, open site/talk/offline-10.html from the file: the whole talk in one file (live slides show as screenshots).

Everything, the POCs and a ruv.sgit run on a local vault server (set up once while online, then no network):

bash scripts/offline.sh setup    # once, online: npm ci (Ruflo, RuVector, MetaHarness, pinned) + .venv with sgit-ai and the SG/Send vault server
bash scripts/offline.sh all      # offline: doctor, POC1/3/4/5, sync + validate the site, one ruv.sgit run (open, deliver, close, delete), serve on :8080

Steps one at a time: doctor, pocs, run, serve. The laptop run's ledger goes to out/offline/, not the public ledger; its keys to ~/.ruv-sgit-offline (mode 0600). Needs Node 20+ and Python 3.11+. Details in the README.

Six steps

  1. Clone the repository

    git clone https://github.com/SGit-AI/SGit-AI__Website__Ruv.git ruv-x-sgit-pocs
cd ruv-x-sgit-pocs

    Read CLAUDE.md (the builder's own mandate) and BRIEF.md first.

  2. Install the pinned npm packages, with install scripts

    npm ci                      # uses package-lock.json; builds better-sqlite3
npm ls ruflo @ruvector/wasm ruvector metaharness --depth=0

  3. Install sgit

    pip install sgit-ai==0.21.0
sgit --version              # sgit-ai v0.21.0
sgit help all               # the full surface; the commands used here: create clone write commit push publish history branch vault

  4. Run the POCs that need no secrets

    npm run abp:gate            # ABP gaps: 0  (exit 1 on any gap: the policy is a test)
npm run poc1                # legacy vs enforce + receipts → out/poc1/
npm run poc3                # RVM rights per role → out/poc3/rvm-caps.md
npm run poc4:build          # browser app → out/app/
npm run poc5                # MetaHarness scaffold → ABP + diff → out/poc5/
npm run cleanup             # stops the Ruflo daemon it auto-starts

    Outputs under out/ are ignored by git; the recorded ones are under evidence/.

  5. Create the two vaults and store the keys

    export SGIT_TOKEN=…                                   # your SG/Send access token, never in argv of anything you log
sgit --token "$SGIT_TOKEN" create ruv-pocs-public     # prints the vault key and the read key ONCE
sgit --token "$SGIT_TOKEN" create ruv-pocs-memory
# save both vault keys as SGIT_VAULT_KEY_PUBLIC and SGIT_VAULT_KEY_MEMORY (repo secrets, or your keychain)
# seed each with a first commit: a vault with zero commits cannot be cloned
cd ruv-pocs-memory && echo "# memory" > README.md && sgit commit -m init && sgit push && cd ..

    Keys are secrets. sgit create prints the key once; there is no reset. Pass keys on stdin (printf '%s' "$KEY" | sgit clone - dir), mask them in CI (::add-mask::), and run git diff before every commit. Publishing with --visibility public reveals the read key for ever: only the public vault.

  6. Write the outputs to the public vault, publish, serve; run the memory roundtrip

    VAULT_KEY="$SGIT_VAULT_KEY_PUBLIC" scripts/vault_write.sh out "runs/local-$(date +%Y%m%dT%H%M)" "pocs: local run" .vault-public
cd .vault-public && sgit publish --visibility public --yes && sgit vault serve --open && cd ..

export VAULT_KEY="$SGIT_VAULT_KEY_MEMORY"
ROLE=coder  bash poc/poc2-agent-memory-in-vault/run.sh write
ROLE=tester bash poc/poc2-agent-memory-in-vault/run.sh write
rm -rf .vault-memory && bash poc/poc2-agent-memory-in-vault/run.sh read

CI and secrets

.github/workflows/pocs.yml runs on every push to dev or main, on pull requests (without the vault jobs) and on demand.

  • build: Node 20, Python 3.11, npm ci, ABP gate, POC1, POC3, POC4 build, POC5, daemon cleanup, upload out/.
  • publish-to-vault: in the protected environment vault (a named person approves: that is the ABP's approval row for create.record.world), writes out/ to ruv-pocs-public under runs/<run_id>/, publishes with the read key.
  • poc2-write (matrix coder, tester, serial) then poc2-read on a different, fresh runner.

Secrets (Settings → Secrets and variables → Actions): SGIT_TOKEN, SGIT_VAULT_KEY_PUBLIC, SGIT_VAULT_KEY_MEMORY. Environment (Settings → Environments): vault, with a required reviewer.

.github/workflows/deploy-pages.yml builds the POC outputs, copies them into site/data, validates the site and deploys site/ to GitHub Pages at ruv.sgit.ai (Settings → Pages → Source: GitHub Actions; DNS for the subdomain already points at GitHub).

This website

Hand-written static HTML under site/, one stylesheet, one script. No framework, no build step for the pages. Diagrams are Mermaid, rendered in the browser from the page source; tables are rendered from the POC output files in site/data/, which site/build/sync.sh copies from out/ and evidence/. site/build/validate.py refuses a broken internal link, a missing image, or anything shaped like a key.

npm run poc1 && npm run poc3 && npm run poc4:build && npm run poc5
bash site/build/sync.sh                 # out/ + evidence/ → site/data, out/app → site/app
python3 site/build/validate.py          # links, images, secrets
python3 -m http.server -d site 8080     # http://localhost:8080

The infographics

Twelve images, generated through OpenRouter's image-output chat models with site/build/gen_infographics.py from the prompts in site/build/infographics.json. Model per job follows newsroom.sgit.ai's bake-off: labelled diagrams on Gemini 3 Pro Image, concept slides on the cheapest Gemini image model, Nano Banana 2.1 first when it is not rate-limited upstream. Every prompt ends with the aspect ratio and "No other text"; invented values are the known failure mode, which is why the facts are in the tables and the images only illustrate.

Risks and unknowns we kept in view

  • Third-party versions move fast (14 new rUv repos in Aug and Sep). Pin, and trust --help over any doc, including this page.
  • Ruflo auto-starts a background daemon; stop it in every script and CI job.
  • Ruflo policy administration requires an interactive terminal by design. Do not bypass it; use the library engine (POC1) or your own terminal (POC6).
  • The native ruvector CLI needs platform binaries; POC4 uses the WASM build, which is verified.
  • Claims about rUv's projects: "per its README", with a link. Star counts are snapshots.
